# План: харвестер сам решает по видео

Дата: 2026-10-23. Ветка `feat/harvester`. База перед работой: коммит `daba963`, 86 тестов.

## Цель

Бот перестаёт спрашивать про каждое видео. Там, где по ответам Некита уверенность ≥ 90%, решает сам (✅ или ❌), спрашивает только серую зону. Дубли отклоняет сам. Раз в день сводка с возможностью вернуть.

## Решения Некита (23.10.2026, не пересматривать)

- Калибровка: по 25 ответов на канал, топ-6 каналов по очереди видео.
- Причина отказа: ❌ как сейчас, потом необязательные кнопки «😴 неинтересно / 🔁 дубль / 📢 реклама».
- Порог авто: 90%.
- Отчёт: сводка раз в день с кнопкой посмотреть и вернуть.
- Авто-✅ разбирается, но видео (Whisper + кадры) только ночью и с лимитом.
- Каналы без своих ответов: спрашивать, как сейчас. Канал сам уходит в авто, когда наберётся ответов.
- Почти тот же текст, что уже был: авто-❌ как дубль, видно в сводке.

- Фильтр рекламы на входе уже есть (`ad_markers`), в очереди с «реклама/erid» в тексте всего 10 постов.

## Как будет решать (простое и проверяемое правило, без ML-библиотек)

Для каждого канала посты делятся на ячейки: 4 корзины похожести (`<0.55`, `0.55-0.65`, `0.65-0.75`, `≥0.75`) × 2 по длине подписи (`<200`, `≥200`), итого 8 ячеек.

В ячейке считаем сглаженную долю ✅: `p = (✅ + 1) / (ответов + 2)`.
- `p ≥ 0.90` → авто-✅ (минимум 8 из 8 ✅);
- `p ≤ 0.10` → авто-❌ (минимум 0 из 8 ✅, или 1 из 18 и т.д.);
- иначе → спросить.
- В ячейке меньше 8 ответов → берём объединённую ячейку канала по той же корзине похожести без деления по длине. Там тоже меньше 8 → спросить.

Почему не строгая граница Уилсона: при нуле ✅ она требует 35+ ответов в одной ячейке, с 25 ответами на канал правило не включилось бы никогда. Сглаженная доля соответствует выбору Некита «из 10 авто-❌ примерно 1 могла быть полезной», а честность проверяется отложенной выборкой (задача 4) и dry-режимом (задача 9).

Почему так в целом: решение объяснимо одной строкой («Наше тело, похожесть 0.6-0.65, короткая подпись: 1 из 20 был полезен»), а ячейки сами перейдут в авто, когда ответов станет больше. Честно: у каналов с 25 ответами многие ячейки останутся «спросить», выигрыш вырастет постепенно. Быстрее всего авто включится у «Наше тело» (233 ответа), «Не баг» (70) и «Эксплойт» (40).

## Задачи

Каждая задача по TDD, коммит после каждой. Живой vault не трогаем, тесты на `tmp_path`.

### 1. Разметка v2
- `labels`: добавить `reason TEXT`, `source TEXT` (`video`/`pilot`/`import`/`auto`), `ts TEXT`. Миграция без потери 637 строк.
- `on_vy`/`on_vn` пишут метку (`source='video'`).
- Разовый бэкфилл: посты с `video_state` в `no`/`yes`/`done` без метки получают её из `video_state`.
- Тесты: миграция на старой схеме, запись метки на кнопки, бэкфилл не перетирает существующие.

### 2. Причина отказа
- После ❌ карточка меняется на «❌ Пропускаю» + кнопки «😴 / 🔁 / 📢». Нажатие пишет `reason`, кнопки исчезают. Не нажал, и ладно.
- Тесты: колбэк причины, повторное нажатие, старая карточка.

### 3. Калибровочная выдача
- Пока у канала из топ-6 меньше 25 ответов, видео-вопросы этого канала идут вперёд очереди, вразброс по ячейкам (а не лучшие по похожести, как сейчас). Остальное как было.
- Список каналов и число берутся из настроек (`video_calib_channels: auto`, `video_calib_n: 25`).
- Тесты: порядок выдачи, остановка после 25, равномерность по ячейкам.

### 4. Модуль правила `harvester/autovideo.py`
- `cells(chat_id) -> stats`, `decide(post) -> ('yes'|'no'|'ask', why)`.
- Настройки: `video_auto: off|dry|on`, `video_auto_conf: 0.9`, `video_auto_min_n: 8`.
- CLI `harvester autovideo report`: по каждому каналу ячейки, сколько ответов и решение, плюс проверка на отложенной выборке (обучаемся на 80% старых ответов, проверяем на 20%): точность авто-✅ и авто-❌ и доля вопросов, которые уйдут.
- Тесты: сглаженная доля на границах (8/8, 0/8, 7/8), объединение ячеек при малом n, канал без ответов → ask.

### 5. Дубли
- Отпечаток текста (нижний регистр, без ссылок, эмодзи и пробелов) плюс эмбеддинг подписи; хранение в новой таблице `post_vecs` для постов с видео за 60 дней.
- Совпадение отпечатка или косинус ≥ 0.95 с уже виденным постом → авто-❌ с `reason='дубль поста N'`.
- Порог 0.95 проверяем на реальных данных до включения (выборка пар показывается Некиту).
- Тесты: точный дубль, репост с другой ссылкой, разный текст на одной картинке не дубль.

### 6. Встраивание в поток
- В `Matcher.process` для статуса `video_ask`: сначала дубль, потом правило.
- `dry`: решение только пишется в лог и в сводку («решил бы так»), вопрос всё равно уходит Некиту. `on`: авто-❌ сразу `rejected`, авто-✅ сразу `video_state='yes'` с пометкой `auto`.
- Вся текущая очередь `ask` (3993) прогоняется через правило тем же путём (команда `harvester autovideo apply`, только в режиме `on`).
- Тесты: три режима, метки `auto` не идут в обучение.

### 7. Видео только ночью
- Авто-✅ видео разбираются только в окне `video_night_window: [1, 7]` и не больше `video_auto_per_night: 30`. Ручные 🎬 как сейчас, сразу.
- Перед Whisper проверка на чужой `mlx_whisper` (`pgrep`): есть чужой, ждём (как `heavy-guard`).
- Тесты: окно, лимит, отложенный запуск при чужом Whisper.

### 8. Сводка раз в день
- В `cards_hour`: «Сам отклонил N (дубли X, по правилу Y), сам взял M, спросил K». Кнопки «Показать взятые / отклонённые»: список со ссылками, у каждого ↩️ вернуть (пост снова `ask`, авто-метка удаляется).
- Тесты: текст сводки, возврат.

### 9. Живой запуск
1. Бэкфилл меток, `autovideo report`: показать Некиту, где правило уже уверено.
2. `video_auto: dry` на 2-3 дня, Некит отвечает как обычно.
3. Сверка: совпадение решений правила с ответами Некита. Включаем `on`, только если ≥ 90% на авто-решениях.
4. `on` + `autovideo apply` по очереди. Утром проверить сводку, диск и своп.
5. Обновить `HANDOFF.md`, `CLAUDE.md` проекта, память `tg_harvester_project.md`.

## Критерии готовности (как проверяем)

- `uv run pytest -q` зелёный, новые тесты на каждую задачу.
- На отложенной выборке старых ответов: точность авто-✅ и авто-❌ ≥ 90% в каждом канале, где правило что-то решает.
- В dry-режиме за 2-3 дня совпадение с ответами Некита ≥ 90%.
- Днём нет авто-Whisper; ночью не больше лимита; свободно на диске ≥ 10 ГБ после первой ночи.
- Вопросов в день меньше, чем сейчас (цифра из сводки до и после).

## Риски

- 25 ответов на канал мало для 8 ячеек: авто будет включаться не сразу. Это нормально, правило осторожное.
- Смена вкуса Некита со временем: старые метки весят столько же. Если заметим, добавим окно «последние 90 дней».
- Порог дублей 0.95 может склеить разные посты с одним шаблоном текста. Поэтому проверка пар до включения и видимость в сводке.
