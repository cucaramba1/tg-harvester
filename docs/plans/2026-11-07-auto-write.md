# Автозапись текста и фото в карантин (план, 07.11.2026)

Статус: правки Некита 07.11 внесены (would_go, лимит 60), ждёт финального «го» после замера качества. Код не тронут.

## Решение Некита (07.11)
- Видео разбирает он сам (🎬/❌), его ответы учат фильтр. Текст и фото система разбирает и пишет в Obsidian сама, без ✅.
- Писать в **отдельный раздел-карантин** со своим MOC и canvas («Telegram авто»), основные разделы не раздувать.
- Потолок **60 заметок в день** (решение 07.11, чтобы быстрее разобрать старую очередь; позже можно вернуть 30).
- Старая очередь (699 `drafted` + 210 `sent` без ответа) идёт через тот же авторежим, в рамках дневного потолка.
- Дубль пропускать, похожее дописывать блоком.
- Фоновый статус и ежедневный отчёт «сколько постов перешло в Obsidian».

Прежний дизайн (10.10): ревью обязательное, автозапись «вернуться через 2 недели». Это осознанная смена правила по решению Некита, карантин + откат её страхуют.

## Как работает сейчас (проверено в коде)
- Ночью `brain.py` делает черновик: `mode` (append/new/skip), `target`, `title`, `content`, `keep_image`.
- Бот в 9:00 шлёт до `cards_per_day` карточек (`send_cards`), ✅ вызывает `Writer.apply`. На сервере `PacketWriter.apply` кладёт пакет, ноут пишет настоящим `Writer`.
- Блоки пишутся с журналом (`blocks`), откат есть у каждого.

## Дизайн

```
ночь 03:00 -> черновики (как сейчас)
  утро (cards_hour) -> auto_write шаг в tick:
     берём drafted без видео, по убыванию score, не больше 60 - уже записанных сегодня
        |- дубль (cosine >= dup_threshold к карантину/записанным)  -> status=duplicate, не пишем
        |- похожая заметка уже В КАРАНТИНЕ                       -> mode=append в неё
        '- иначе                                                  -> mode=new в «Telegram авто/<исходный раздел>/»
     -> PacketWriter.apply -> пакет -> ноут (раз в 5 мин) -> ack -> счётчик дня
```

Решения, которые прошу подтвердить:
1. **Append только внутри карантина.** Если похожая заметка лежит в основном vault, в карантин пишется новая заметка со ссылкой «Связанные заметки» на неё (как сейчас делает `_new`), основные заметки автоматом не трогаются. Иначе карантин не защищает основные разделы.
2. В каждой заметке карантина в frontmatter `would_go: <раздел или заметка>`: куда она пошла бы, если бы не карантин (решение Некита 07.11). Перенос потом по этому полю.
3. Карантин лежит в vault «Obsidian storage», подпапка по исходному разделу, чтобы перенос заметки в настоящий раздел был одним действием.
4. Видео-черновики (`topic`-карточки и enriched-видео) в авторежим **не попадают**, остаются на ✅.
5. Вернуть ручной режим можно флагом `auto_write: off` в `config/settings.yaml`.

## Шаги
1. Настройки: `auto_write` (on/off/dry), `auto_per_day: 60`, `quarantine_section`. Режим `dry` = считает и отчитывается, ничего не пишет (первый запуск).
2. Раздел-карантин: папка, MOC, canvas по стандарту «Правила оформления холстов» (создаёт applier при первой записи или руками).
3. `autowrite.py`: выбор кандидатов, проверка дублей через существующий матчер/`dedup`, переписывание черновика (mode/target), вызов `PacketWriter.apply`. Тесты: дубль, append в карантин, new, потолок, видео не берёт, `off` ничего не делает.
4. Шаг в `tick` после `send_cards` (карточки для видео-тем и спорных остаются как есть).
5. Ежедневный отчёт (в то же утреннее сообщение или отдельным): записано сегодня (новых/дописано), дубли пропущено, осталось в очереди, в карантине всего и сколько старше 14 дней, видео ждут ответа.
6. Статус фона: команда `/stats` в боте + тревога, если пакет `queued` старше суток (ноут не забирает), applier не ходил >2 ч, ночной прогон не отчитался. Сервис-юниты и память сервера в сводку.
7. Прогон `dry` один день, смотрим отчёт, потом `on`. Первые записанные заметки показываю Некиту вместе с откатом.
8. Документы: HANDOFF, дизайн-спека, память; `CLAUDE.md` проекта (правило «в vault только одобренное» меняется).

## Что НЕ делаем сейчас
- Автоудаление старых заметок карантина (раз в неделю только список «старше 14 дней» в отчёте, решает Некит).
- Обучение фильтра текста по удалениям из карантина (идея 2-го этапа: удалил заметку = метка «не надо»).
- Автоперенос из карантина в основные разделы.

## Риски и честные оговорки
- Старая очередь 909 при 60 в день разгребается ~15 дней, плюс новые посты.
- Качество черновиков на «обычных» постах без ревью не измерено. Режим `dry` + первая неделя с откатом это страховка, но не замер.
- Ноут спит: пакеты ждут, заметки появятся при пробуждении.
- Правило vault «без межраздельных wikilinks»: блок «Связанные заметки» в `_new` ссылается на заметки основных разделов. Проверить на аудите vault (`audit.py`), при конфликте ссылки в карантине не ставить.

## Критерии проверки
- Тесты зелёные, новые покрывают пункты шага 3.
- `dry`: отчёт показывает N кандидатов, 0 пакетов в outbox.
- `on`: заметки в «Telegram авто», MOC и canvas обновились, ack пришёл, счётчик дня не больше 60, откат одной заметки работает.
- Отчёт и `/stats` приходят в Telegram.
